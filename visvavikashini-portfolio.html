Explainable AI-Enhanced Quantum-Inspired Cryptographic Framework
A secure-communication architecture unifying BB84-inspired key generation, AES-256 encryption, Random Forest threat classification, and Permutation Feature Importance explainability.
Published +
Python 3.11scikit-learnRandom Forest AES-256 (CBC)BB84 simulationPermutation Feature Importance NumPy / PandasMatplotlib / Seaborn

Digital communication keeps growing, and so does its attack surface — quantum computers threaten classical cryptography (Shor's and Grover's algorithms), while ML-based intrusion detection is accurate but rarely explains itself. This framework closes both gaps at once: it generates a session key the way BB84 quantum key distribution would, encrypts traffic with AES-256, watches communication behaviour for anomalies, classifies threats with a Random Forest, and explains every verdict with Permutation Feature Importance.

Headline results — 1,600 held-out test sessions
98.69%Detection accuracy
0.88%False positive rate
98.75%5-fold CV accuracy
1.000ROC-AUC (attack class)

Trained and evaluated on 8,000 simulated sessions (4,000 Normal · 2,000 Suspicious · 2,000 Attack), 80/20 stratified split. On the confusion matrix: all 400 Attack sessions were caught (0 missed), 793/800 Normal sessions and 386/400 Suspicious sessions were classified correctly, with a small Normal↔Suspicious overlap accounting for the rest.

The 10-step pipeline
Quantum-inspired session key generation (BB84 simulation, 256-bit)
AES-256-CBC encryption with a random IV
Data transmission with live parameter monitoring
Session key verification — mismatch rate computed
Feature extraction across 6 communication features
Feature normalisation (StandardScaler)
Threat detection — Random Forest (200 trees, depth 15)
Classification: Normal / Suspicious / Attack + response
Explainability via Permutation Feature Importance
Final output: classification plus feature-level explanation

Incident & fix — broken access control

In real use, the teacher dashboard was reachable through a predictable, unauthenticated route. Because there was no access check on that page, all exam records were accidentally wiped when it was reached directly. I traced the cause to that missing authorization check, and fixed it by adding proper role-based access control so any unauthorized request now returns an explicit access-denied response instead of the page itself. It was a first-hand lesson in why broken access control is one of the most common real-world vulnerabilities — not just an OWASP checklist item.
